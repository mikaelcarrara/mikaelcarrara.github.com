01 — Visão geral

O que é a Incept 48

Uma fábrica de MVPs onde a IA faz o discovery e o build. O cliente fala, prioriza, e o Claude Code escreve, testa e faz deploy do produto.

Um operador humano supervisiona. Nenhum dev executa manualmente. A maioria das agências leva 6 semanas para entregar um MVP — 2 de discovery, 1 de proposta, 3 de execução. A Incept 48 elimina tudo que é cerimônia e comprime o que é valor.

Perspectiva interna
Fluxo do operador

O operador não escreve features na unha. Ele configura contexto, define guardrails e orquestra o Claude Code durante as 48 horas.

1
Configuração de contexto de produto e design

O operador parte da transcrição, backlog e protótipo para montar o contexto de trabalho do Claude: visão de produto, princípios de UX, linguagem de marca, restrições técnicas e prioridades de negócio.

2
Definição de guardrails

No cockpit interno (Incept 48), o operador define limites explícitos: o que o Claude pode ou não alterar, padrões de arquitetura aceitos, contratos de API, políticas de segurança e dados que nunca podem ser expostos.

3
Orquestração de agentes e ferramentas

O Incept 48 conecta o Claude Code ao repositório, CI/CD e infraestrutura. O operador escolhe templates de prompt — build, testes, refactor, migrações — e ativa ou pausa fases do pipeline.

4
Acompanhamento e intervenção mínima

Durante as 48 horas, o operador acompanha diffs, PRs e logs. Intervém apenas para corrigir rota: recortar escopo, pedir refactor ou ajustar uma decisão de UX crítica.

5
Aprendizado contínuo dos templates

As decisões tomadas pelo operador alimentam os templates de contexto e guardrails do Incept 48. A cada projeto, o sistema fica melhor em traduzir briefing de negócio em instruções acionáveis para o Claude Code.

03 — Experiência do cliente

O que o cliente vê

O cliente não vê código, reuniões de alinhamento ou planilhas. Ele vê um dashboard e quatro notificações.

Assim que contrata, o cliente ganha acesso a um ambiente autenticado. Emails são apenas pings de notificação — nada de PDF em anexo, nada de instrução por email.

  • Status do build em tempo real: etapa atual e progresso
  • Backlog gerado pela IA com score de ROI por feature
  • Interface de priorização de features
  • Credenciais e links de entrega disponíveis após o deploy
  • Histórico de atualizações do projeto

O contexto que o Claude Code recebe

Antes de iniciar o build, o operador monta e valida o seguinte contexto:

Stack: Next.js + Supabase + Stripe Features confirmadas: — Gerador de propostas automático (8pts) — Rastreamento de abertura de proposta (5pts) Critérios de aceite: [por feature, gerados pela IA] Variáveis de ambiente: STRIPE_KEY, RESEND_API_KEY, SUPABASE_URL...

O Claude Code não recebe um brief genérico — recebe escopo travado, critérios mensuráveis e stack definida. Isso é o que torna o build previsível.

05 — Negócio

Por que o modelo funciona

Margem

O custo marginal de um build é próximo de zero — o Claude Code não cobra por hora de dev, o Whisper custa centavos por reunião. O que vendemos é confiança na entrega: escopo bem definido, IA supervisionada, processo sem fricção.

A etapa mais cara em qualquer agência — discovery e execução — é automatizada aqui. O humano existe para garantir qualidade, não para produzir.

Escala

O modelo escala porque o custo de entregar o décimo MVP é praticamente igual ao custo de entregar o primeiro. O gargalo não é execução — é aquisição de clientes.

  • Cada operador pode supervisionar múltiplos builds em paralelo
  • O dashboard é o mesmo para todos os clientes — zero custo de onboarding
  • A stack entregue é padronizada — suporte é previsível
